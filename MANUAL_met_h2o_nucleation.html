Meteorological Nucleation

A manual for met_h2o_nucleation.py — the application and diagnosis layer that sits on top of the validated unified_h2o_nucleation_climate core, turning Ferreira's Eq.39a/39b shifted-equilibrium nucleation physics into a meteorological precipitation-favourability diagnosis with xarray/NetCDF I/O.

liquid (condensation) ice (deposition) vapour subsaturated / no-solution

Overview

What this layer is — and isn't

It is an application/diagnosis layer: given an atmospheric state (temperature, pressure, humidity, vertical velocity, water contents, cooling rate, timestep, cell volume) it resolves the local nucleation state via the validated core, decomposes the free energy, computes the nucleation rate and expected_events = I·dt·V_cell, and emits a precipitation-favourability diagnosis (rain/snow/graupel/hail indices + a diagnostic class) with explicit confidence and caveats.

It is not a hydrometeor-growth model and not an operational forecast. Condensation/deposition, collision–coalescence, accretion, riming, melting and refreezing are not modelled. High I flags nucleation favourability, never a rain/hail forecast. The diagnosis states exactly which dynamic and microphysical data an operational forecast would still require.

The validated core is bundled in this repository and imported read-only (importlib, SHA-256 guarded); it is never modified by this layer. All closure, critical-radius, surface-stress and rate physics is delegated to it.

Physics in one lineClassical theory fixes the critical radius at a single equilibrium; this framework (Ferreira, Eq. 39a/39b) nucleates under a thermal gradient ∇T that shifts the local equilibrium, so the germ sees P_eq,shift = P_sat,phase(T_local). The closure F(g;r)=Γ²/(4πr²)−g=0 ties ∇T to the continuation radius (Brent-solved, or set with --gradT); the critical radius is the 2nd-order parabolic root r_critical_2nd_m. Read ∇T as the local interface gradient (1–10⁴ K/m), not a synoptic front.

Setup

Install & requirements

Requires Python 3.9+. numpy, scipy and matplotlib are required — the bundled core imports all three at load time (matplotlib is forced headless, Agg). The repository is self-contained: the validated core, the het_contact_angle module and the two SHA-256-guarded reference models are all bundled, so no PYTHONPATH or external checkout is needed.

Quick start

Validate the environment and prove the core is untouched, then run the canonical reference point:

python met_h2o_nucleation.py --validate

The CLI prints the full 48-field report per phase. Add --json report.json to capture it verbatim.

Humidity

Humidity resolution

Humidity is accepted as RH [%], p_v [Pa], or (via the API) mixing ratio / specific humidity. resolve_humidity cross-checks all supplied forms (≤1 % relative) and reuses the core SaturationProperties for the RH↔p_v↔mixing-ratio↔dew/frost-point conversions. At least one form is required.

Free energy

Free-energy decomposition

free_energy_decomposition(model, st, theta) uses the model's own hooks (surface_energy, bulk_entropy_change, molar_volume, ftheta) — no re-derivation:

ΔG_V = ΔS_V · ΔT ΔG_bulk = (4π/3) r³ ΔG_V ΔG_surface = 4π r² γ(r, T_local) ΔG_config = [f(θ)/4 − 1] · (ΔG_bulk + ΔG_surface) (=0 for homogeneous θ=π) ΔG_total = ΔG_bulk + ΔG_surface + ΔG_config ΔG_C = ΔG_total(r_C)

Diagnosis

Precipitation diagnosis

PrecipitationDiagnosis sets a diagnostic_class from S_w, S_i, T and phase, and emits four 0–1 favourability indices (rain/snow/graupel/hail), each with contributing vars, missing vars, confidence and a short physical explanation.

Honesty guardIndices combine nucleation tendency with available dynamics/microphysics (w, LWC/IWC, cooling rate, freezing level, residence time). When those are absent the index reflects thermodynamic favourability only, with LOW confidence and the caveat "Thermodynamically favourable to nucleation, but the dynamic and microphysical data are insufficient to confirm precipitation or hail." Never returns hail/rain solely because I is high.

Output

MetNucleationReport — the 48-field schema

Per phase: the full mandatory schema + metadata (units, sign conventions, correlation sources, validity ranges), assumptions, warnings, validity_flags. Stability is distinguished via in_valid_range + S_w/S_i + T vs the triple point (stable / metastable / extrapolated).

Key fields include status, nucleation_mode, contact_angle_deg (the nucleation angle θ solved by Ferreira Eq. 17), S_water, S_ice, gradT_K_m, r_critical_2nd_m, log10_nucleation_rate, expected_events, dominant_phase, the four favourability indices, confidence, and diagnostic_class.

Driver

MetNucleationRunner

Builds the core AtmosphericInput, calls UnifiedNucleationSimulator.evaluate_point for admissible phases (auto/both), and assembles per-phase core results + free-energy decomposition + expected_events + precipitation diagnosis into a MetNucleationReport. Loops over z (profile), t (time series) and grid (xarray fields). Solver iterations are captured via brentq(..., full_output=True).

Tested runs

CLI cases with verified output

The runs below were executed from the repo root with the --summary flag and their terminal output captured verbatim. --summary prints the compact one-row-per-phase table (status, saturation ratios, solved gradient, 2nd-order critical radius, log10 I, dominant phase, the four favourability indices, the diagnostic class, and expected_events) — this is exactly what is shown in each block below. Without --summary the CLI instead prints the full 48-field vertical report (one field per line, under a per-phase header), which is what is written verbatim to --json. The summary table and the full report carry the same values; only the layout differs.

Variable key — every column in the example outputs

Case 1

Both phases, supersaturated, with dynamics + expected events

The canonical reference point: 260 K, 700 hPa, 110 % RH over water, a modest updraft, supercooled LWC/IWC, and a timestep × cell volume so expected_events is determined.

python met_h2o_nucleation.py --T 260 --P 70000 --RH 110 --phase-mode both --w 2.0 --LWC 5e-4 --IWC 1e-4 --dt 60 --Vcell 1e6 --summary
terminal
phase | status | S_w | S_i | gradT | rC2nd | log10I | dominant | rain | snow | graup | hail | class | exp_events liquid | ok | 1.10 | 1.25 | 74.33 | 5.11e-06 | 53.10 | liquid | 0.600 | 0.607 | 0.555 | 0.386 | mixed_phase | 7.61e+60 ice | ok | 1.10 | 1.25 | 148.1 | 4.20e-06 | 49.08 | liquid | 0.600 | 0.607 | 0.555 | 0.386 | mixed_phase | 7.20e+56

ReadBoth phases supersaturated (S_w=1.10, S_i=1.25). Liquid wins kinetically (log₁₀I 53.1 vs 49.1); r_C,2nd ≈ 5.1e-6 m (liquid), 4.2e-6 m (ice). With dt=60 s and V_cell=1e6 m³, expected_events = I·dt·V_cell is enormous (≈7.6e60 liquid) — nucleation is not the bottleneck here; growth is (unmodelled). Class mixed_phase (supersaturated wrt both phases, T<0 °C).

Case 2

Auto phase mode (dominant phase reported)

Same state, but --phase-mode auto: both admissible phases are computed and the kinetically dominant one is reported. Without --dt/--Vcell, expected_events is "undetermined".

python met_h2o_nucleation.py --T 260 --P 70000 --RH 110 --phase-mode auto --summary
terminal
phase | status | S_w | S_i | gradT | rC2nd | log10I | dominant | rain | snow | graup | hail | class | exp_events liquid | ok | 1.10 | 1.25 | 74.33 | 5.11e-06 | 53.10 | liquid | 0.750 | 0.776 | 0.776 | 0.664 | mixed_phase | undetermined ice | ok | 1.10 | 1.25 | 148.1 | 4.20e-06 | 49.08 | liquid | 0.750 | 0.776 | 0.776 | 0.664 | mixed_phase | undetermined

Readdominant_phase = liquid (Δlog₁₀I ≈ 4 decades). The favourability indices themselves are unchanged from Case 1; the higher values reflect the thermodynamic-only confidence reported when dynamics are absent. expected_events is "undetermined" because no timestep/cell volume was supplied.

Case 3

Ice-only, RH = 130 %

Force the ice phase and drive it hard against the sublimation curve (S_i = 1.51). Useful for cirrus / ice-cloud regimes.

python met_h2o_nucleation.py --T 258.15 --P 70000 --RH 130 --phase-mode ice --summary
terminal
phase | status | S_w | S_i | gradT | rC2nd | log10I | dominant | rain | snow | graup | hail | class | exp_events ice | ok | 1.30 | 1.51 | 147 | 4.20e-06 | 49.08 | ice | 1.000 | 0.792 | 0.792 | 0.687 | mixed_phase | undetermined

ReadOnly ice is computed; dominant = ice (no competitor). RH_i is 1.51 by construction (RH = 130 % wrt water ⇒ S_i = 1.51 at 258.15 K); RH_w (=1.30) is still reported for cross-reference. The rain index saturates at 1.0 because the warm-rain supersaturation factor (S_w−1)/0.20 clips at 1 — a thermodynamic rain favourability, not a rain forecast.

Case 4

Heterogeneous nucleation, θ solved by Ferreira Eq. 17

Switch to heterogeneous mode. The nucleation angle θ is no longer fixed: the core solves it self-consistently from Eq. 17 (r_C,Het/r_C,Hom) and reports it as contact_angle_deg. Compare log₁₀I against Case 2 (homogeneous).

python met_h2o_nucleation.py --T 260 --P 70000 --RH 110 --phase-mode both --mode heterogeneous --theta 60 --summary
terminal
phase | status | S_w | S_i | gradT | rC2nd | log10I | dominant | rain | snow | graup | hail | class | exp_events liquid | ok | 1.10 | 1.25 | 74.33 | 5.11e-06 | 50.93 | liquid | 0.750 | 0.776 | 0.776 | 0.664 | mixed_phase | undetermined ice | ok | 1.10 | 1.25 | 148.1 | 4.20e-06 | 46.91 | liquid | 0.750 | 0.776 | 0.776 | 0.664 | mixed_phase | undetermined

ReadThe solved contact_angle_deg ≈ 180° (reported for both phases): the core/model carries no substrate (aerosol) surface energies (γ_AC, γ_BC), so the Eq. 17 self-consistency r_C,Het(θ) = r_C,Hom·ratio(θ) has only the trivial homogeneous-limit root θ = π. The supplied --theta 60 is the brentq fallback and is not used here — a non-trivial θ < 180° would require substrate surface energies the core does not currently model. log₁₀I drops ~2.2 decades vs Case 2 (53.10→50.93 liquid) because the heterogeneous rate uses the solved-θ barrier/prefactor (full-sphere geometry at θ = π), not a fixed 60° cap. r_C,2nd is unchanged — it comes from the validated core closure, independent of the contact angle.

Case 5

Prescribed thermal gradient (∇T = 1e3 K/m)

Override the closure: prescribe the gradient instead of Brent-solving it. A steeper gradient shrinks the continuation radius and shifts the local state.

python met_h2o_nucleation.py --T 260 --P 70000 --RH 110 --phase-mode both --gradT 1e3 --summary
terminal
phase | status | S_w | S_i | gradT | rC2nd | log10I | dominant | rain | snow | graup | hail | class | exp_events liquid | ok | 1.10 | 1.25 | 1101 | 1.34e-06 | 51.94 | liquid | 0.750 | 0.776 | 0.776 | 0.664 | mixed_phase | undetermined ice | ok | 1.10 | 1.25 | 1142 | 1.52e-06 | 48.20 | liquid | 0.750 | 0.776 | 0.776 | 0.664 | mixed_phase | undetermined

ReadForcing ∇T = 1e3 K/m (≈14× the solved value of Case 2) collapses r_C,2nd from ~5.1e-6 m to ~1.3e-6 m and lowers log₁₀I by ~1.2 decades. The saturation ratios are unchanged (they depend on T and p_v, not the gradient). The gradient is an independent control, not a consequence of supersaturation.

Case 6

Subsaturated state (no nucleation)

At 80 % RH both phases are subsaturated. In auto mode the tool must not fabricate a rate: it returns status = subsaturated, NaN nucleation fields, and dominant = none.

python met_h2o_nucleation.py --T 258.15 --P 70000 --RH 80 --phase-mode auto --summary
terminal
phase | status | S_w | S_i | gradT | rC2nd | log10I | dominant | rain | snow | graup | hail | class | exp_events liquid | subsaturated | 0.80 | 0.93 | undet. | undet. | undet. | none | 0.000 | 0.125 | 0.125 | 0.188 | subsaturated | undetermined ice | subsaturated | 0.80 | 0.93 | undet. | undet. | undet. | none | 0.000 | 0.125 | 0.125 | 0.188 | subsaturated | undetermined

BehaviourS_w = 0.80, S_i = 0.93 — both below 1. status = "subsaturated", all nucleation fields "undetermined", dominant = "none". Skip RH and supply the vapour partial pressure directly. At 260 K this is strongly supersaturated wrt both phases (S_w = 2.25).

Case 10

Warm-moist × cold-dry air-mass collision (frontal mixing cloud)

A warm, moist air mass (T = 293.15 K, RH = 95 %) collides with a cold, dry one (T = 268.15 K, RH = 40 %) at a near-surface front (P = 900 hPa). Neither parent is saturated, yet isobaric mixing (mix T and p_v linearly — the Rogers–Yau mixing-cloud construction) yields a supersaturated parcel: scanning the warm-air mass fraction f, S_water peaks at f = 0.50 ⇒ T = 280.75 K, p_v = 1203.69 Pa, S_water = 1.153. That mixed state is the frontal cloud. example_met_frontal_collision.py builds it (re-using the core SaturationProperties correlations) and diagnoses it; the CLI below runs the mixed state directly, with a modest updraft over the cold wedge.

python met_h2o_nucleation.py --T 280.75 --P 90000 --p-v 1203.69 --phase-mode both --w 1.5 --LWC 5e-4 --dt 60 --Vcell 1e6 --summary
terminal
phase | status | S_w | S_i | gradT | rC2nd | log10I | dominant | rain | snow | graup | hail | class | exp_events liquid | ok | 1.15 | 1.07 | 78.71 | 5.11e-06 | 53.05 | liquid | 0.641 | 0.452 | 0.431 | 0.375 | warm_rain | 6.79e+60 ice | ok | 1.15 | 1.07 | 160.8 | 4.20e-06 | 49.10 | liquid | 0.641 | 0.452 | 0.431 | 0.375 | warm_rain | 7.63e+56

ReadThe collision is not itself a tool input — it is encoded as the mixed parcel it produces. Both parents were subsaturated (RH 95 % and 40 %), yet the mixture reaches S_water = 1.15 because P_sat,w(T) is convex and the straight mixing line bulges above it: this is mixing fog / frontal cloud. T = 280.75 K > 273.15 K, so the class is warm_rain and liquid dominates (log10I 53.05 vs 49.10 for ice); ∇T is solved by the thermal closure (78.7 K/m liquid). The peak-supersaturation mixture is warm — for a supercooled / mixed-phase ice case pick a colder mixture (larger cold-air fraction, T < 273 K) from the same T_mix/S_mix scan the script computes. Do not map the synoptic front's ∇T onto --gradT: that field is the local interface gradient (validated 1–1e4 K/m), not the ~1e-3 K/m synoptic gradient.

Conventions

Sign and naming conventions

  • ftheta(θ) = 2 − 3cosθ + cos³θ (unnormalized 0–4); heterogeneous_factor = fθ/4 (0–1). θ = π ⇒ homogeneous.
  • Subscripts: _water / _ice for saturation-ratio reference; 2nd for the 2nd-order (Eq.39b) critical radius; _het for the heterogeneous parabola.
  • Undetermined fields use the sentinel "undetermined", never a silent NaN that looks like a computed zero.
  • expected_events = I · dt · V_cell only when dt and V_cell are both supplied; else the sentinel.
  • r_C,2nd is reported in micrometre order at the default r_ref = 1e-7 m; a sub-micron r_C,2nd indicates a bad r_ref, not a closure bug.

Validity

What is validated, what is hypothesis

CategoryCovers
Math validationclosure residual (~1e-16), 2nd-order parabola residual, classical limit r_C,1st vs CNT
Numerical verificationIAPWS/Goff-Gratch round-trips, bracket-independence, SHA-256 core guard
Reference comparison1st-order Gibbs-Thomson vs CNT (~1.0–2.0e-8 K·m)
Experimental / hypothesisprecipitation favourability indices, diagnostic class — flags, not forecasts; hydrometeor growth unmodelled

Out of scopeCondensation/deposition growth, collision-coalescence, accretion, riming, melting/refreezing are NOT modelled. The diagnosis flags favourability and states which dynamic/microphysical data (w, LWC/IWC, CCN/INP, cooling rate, freezing level, residence time, hydrometeor trajectories) an operational rain/hail forecast would still require.

Help

Troubleshooting

SymptomCause & fix
ModuleNotFoundError: het_contact_angle (or the core)Run from the cloned repo root. het_contact_angle.py and the unified_h2o_nucleation_climate/ core are bundled there; if you copied only met_h2o_nucleation.py elsewhere, copy the siblings too or put the repo root on PYTHONPATH.
--validate → ice reference script not found / VALIDATION FAILEDThe SHA-256 guard needs the two reference models (Nucleation_model_H2O_vapour_solid_Sim_2026_paper.py, …_liquid_Sim_2026.py) at the repo root, one level above unified_h2o_nucleation_climate/. They are bundled; copy them if you took only the module.
ImportError for scipy or matplotlibBoth are required — the bundled core imports them at load. pip install -r requirements.txt. matplotlib uses the headless Agg backend, so no display is needed.
NetCDF read/write warns about the engine or failsto_netcdf/from_netcdf fall back netcdf4 → h5netcdf → scipy; with only scipy you get NetCDF3. pip install netCDF4 for NetCDF4/HDF5.
from_grib raises RuntimeErrorGRIB ingestion needs cfgrib + eccodes (pip install cfgrib eccodes).
Every physics field undetermined, status = subsaturatedThe state is below saturation (S<1) in auto/single-phase mode — correct behaviour, not an error. Raise --RH/--p-v, or use --phase-mode both to force the closure.
r_critical_2nd_m comes out sub-micronUsually a bad --r-ref; the default 1e-7 m gives µm-order critical radii.
Unicode / cp1252 errors printing on WindowsThe examples wrap stdout as UTF-8. If you print reports yourself, set PYTHONUTF8=1 or reconfigure stdout to UTF-8.
